# V16 r5：Hotelling 原理与实现审查

本文只说明 `model/covariance_revision.py` 的数学定位与稳定性检查，不提前声称新窗口或 r5 已取得指标提升。与 r4 相同的统计变换和前向计算保持不变；本次额外输出数值诊断。

## 原理真正进入了哪些部分

Hotelling 线性观察者以类均值差 `delta` 和类内协方差 `Sigma` 构造线性方向 `w ∝ Sigma^-1 delta`，最大化线性可检测性 `(w^T delta)^2 / (w^T Sigma w)`。该 Rayleigh 商结论不需要高斯假设；把它进一步等同于最优似然比检验则需要额外分布条件。

当前实现将这一原则用于训练集拟合的 Fisher 通道和类内协方差度量，再用一个小型非线性头产生有界分数修正。它不是经典线性 HO 检验器，推荐称为 **Hotelling-inspired covariance-aware context revision（Hotelling 原理启发的协方差上下文修正）**。通道降维本身是已有 HO 研究路线；本实现的 Fisher + PCA 也不能冒称为文献中的自动编码器通道。

参考：[Granstedt、Zhou、Anastasio，Approximating the Hotelling Observer with Autoencoder-Learned Efficient Channels for Binary Signal Detection Tasks](https://arxiv.org/abs/2003.02321)。论文区分了 Bayesian ideal observer 与 optimal linear Hotelling observer，并研究通道降维的计算与估计作用。

## 矩阵方向已核对

联合向量按 `[u2; u1]` 排列，第二次观察在前。记正则化类内协方差为：

\[
\Omega=\begin{bmatrix}\Omega_{22}&\Omega_{21}\\\Omega_{12}&\Omega_{11}\end{bmatrix},\quad
R=\Omega_{12}\Omega_{22}^{-1},\quad
S=\Omega_{11}-R\Omega_{21}.
\]

代码的 `solve(Omega22, Omega12.T).T` 正是上述 `R`。若 `L2 L2^T = Omega22`、`Lr Lr^T = S`，则变换为：

\[
T=\begin{bmatrix}L_2^{-1}&0\\-L_r^{-1}R&L_r^{-1}\end{bmatrix},\qquad
T\Omega T^\top=I.
\]

`F.linear(joint, T)` 对行向量实施 `joint @ T.T`，与该列向量公式一致。对应的 Mahalanobis 距离有精确分解：

\[
\delta^\top\Omega^{-1}\delta
=\delta_2^\top\Omega_{22}^{-1}\delta_2
+(\delta_1-R\delta_2)^\top S^{-1}(\delta_1-R\delta_2).
\]

该恒等式针对正则化后的矩阵。它不等于概率独立性、语义重复 B 的删除、贝叶斯后验更新或实际 IoU 增益。

## 重要反例：复制观察也可能出现正的“条件增量”

令两次观察完全相同，类内方差为 `v`，类均值差均为 `delta`。它们不可能提供超出单次观察的新信息。若采用代码中的对角收缩强度 `rho` 和相对 ridge `epsilon=1e-5`：

\[
\Omega=v\begin{bmatrix}1+\epsilon&1-\rho\\1-\rho&1+\epsilon\end{bmatrix}.
\]

虽然真实观测仍只有一个自由度，正则化使矩阵满秩。直接代入 Schur 分解得到：

\[
\frac{d_{\mathrm{conditional}}^2}{d_{\mathrm{second}}^2}
=\frac{\rho+\epsilon}{2-\rho+\epsilon}>0.
\]

因此报告中的 `fisher_conditional_increment` 是**正则化度量的条件距离**，不能解释成新增信息量。此反例已加入测试：完全相同的输入和编码观测均只有一个自由度，但该距离为正，且白化与 Schur 恒等式依然成立。真实互补收益必须通过同容量、独立拟合的 `no_context` 对照和验证集指标证明。

## 稳定性诊断及解释

拟合报告新增以下纯诊断字段，不改变任何权重、统计量或前向结果：

| 字段 | 含义 |
|---|---|
| `minimum_eigenvalue` | 正则化联合协方差 Omega 的最小特征值，保留原有字段 |
| `regularized_condition_number` | Omega 的最大/最小特征值比 |
| `schur_minimum_eigenvalue` | Schur 协方差 S 的最小特征值 |
| `schur_condition_number` | S 的最大/最小特征值比 |
| `transform_spectral_gain` | 条件变换 T 的最大奇异值，表示最坏方向的线性放大倍数 |

上述诊断采用拟合使用的 CPU float64 矩阵计算。它们不包含原始特征标准化、61→8 投影或非线性头的增益，也不等于 float32 部署误差测量。对于此白化变换，`||T||_2 = 1 / sqrt(lambda_min(Omega))`，测试同时核对该关系。Cholesky 成功只表明可分解，不自动说明条件数小或放大倍数小。

有限训练录像、录像内事件相关性及罕见背景尾部都会使总体协方差估计不充分。收缩和 ridge 改善数值可用性，但不保证消除这些统计风险。当前第一层范数约束描述的是正则化度量下的线性增益，不是实际非高斯背景尾部误报率的上界。

## r5 及大窗口实验的约束

100/50、200/100、400/200 ms 应分别完成对应窗口的骨干适配，然后冻结骨干，重新拟合均值、尺度、通道和协方差。不得跨窗口直接复用旧统计量并称其仍然匹配当前特征分布。冻结后的小头拟合不会改变这些统计坐标。

逐录像平衡和 FN 参考约束用于避免少数高事件量录像主导目标，它们属于优化目标的设计，不改变 HO 的数学适用范围。普通非凸 Lagrangian 更新并不自动保证真实召回、Pd、Fa 或四指标共同改善；应以训练集拟合、验证集选择和零修正候选提供工程上的退路，测试集仅做最终报告。

参考：[Cotter、Jiang、Sridharan，Two-Player Games for Efficient Non-Convex Constrained Optimization](https://proceedings.mlr.press/v98/cotter19a.html)。该工作明确讨论普通 Lagrangian 在非凸情形的局限；当前代码没有实现其完整 proxy-Lagrangian 博弈算法，因此不继承该论文的保证。

## 可主张与不可主张

可主张的是：用低维类内协方差组织同一事件片段的相关上下文，并以有界修正和漏检约束训练轻量读出。是否具有独立互补贡献、是否降低误报和增加 IoU，仍需实验成立。

不可主张的是：精确消除重复信息、最优贝叶斯序贯检验、保证召回不降、保证所有窗口有效，或把 HO / Schur 补 / 重叠滑窗本身当作本项目原创。

## 本地验证结果（2026-11-13）

完整流水线是“按窗口适配骨干 → 冻结 → 重新拟合统计量 → 训练修正头”。以下探针只检验固定旧 r2 表示上的修正头，不代替完整流水线实验。全部 99 条训练录像、24 条验证录像，seed37，固定阈值 0.9，没有读取 test。

| 固定旧 r2 表示上的读出 | Val IoU % | 目标事件召回 % | Pd % | Fa ×10^-6 |
|---|---:|---:|---:|---:|
| 只用第二次读出 | 86.805152 | 91.159588 | 91.096178 | 6.319440 |
| r5 逐录像风险 full | 86.919764 | 91.187067 | 91.096178 | 6.106125 |
| r5 同容量 no_context | 86.884435 | 91.197753 | 91.159177 | 6.174267 |
| 原 r4 full | 87.081535 | 91.173328 | 91.159177 | 5.658758 |

r5 full 相对第二次读出增加 0.114612 个 IoU 百分点，Fa 降低约 3.38%，但相对 no_context 仅增加 0.035328 个百分点，而且低于旧 r4。当前结果不足以证明更强的上下文互补或新目标优于旧目标。

full 选中头仍有 42/99 条训练录像违反各自 smooth-FN 参考，最坏差 0.107938；训练录像宏平均召回下降 0.115084 个百分点。因此 `record_fn_reference` 在当前有限轮非凸优化中是**逐录像风险惩罚**，不能写成已经实现的逐录像召回保护。验证四指标筛选也不等于训练约束可行性或测试泛化保证。

数据与脚本：`Res/v16_r5_cached_probe37/REPORT.txt`、`summary.json`、`tools/v16/probe_r5_cached.py`。统计提取/缓存核验 124.72 秒，全部探针 228.29 秒；这不包含骨干适配训练。

本地实现检查：Python 3.8 / PyTorch 1.9 CPU 的 V16 测试集通过（145 项，2 项跳过），另有 4 项适配阶段权重选择测试通过；三个窗口各自通过骨干阶段与修正头阶段 CUDA 反传预检。三个窗口也分别通过真实分辨率、TBPTT16、跨 chunk 状态衔接的两次更新探针。最后的打包校验修改通过队列及 r5 流水线 39 项测试。上述检查证明执行路径可用，不证明模型指标增长。

## 运行成本与解释限制

- 修正头为 16→8→1 的有界残差读出，144 个可训练参数。当前两个 61→8 投影、16 维变换和 MLP 合计约 1368 MAC / 成对事件；该数不包括骨干、特征读取和非线性计算。
- 不再为每个事件维护多轮 SDU 隐状态或反复查邻域；特征按窗口共享，事件读出与修正按批执行。事件总成本仍然随事件数线性增长，不能称为与事件数无关。
- 训练阶段保留 V5 carry、通信约束、4 streams 和 TBPTT16。骨干适配与修正头各最多 20 轮、至少 8 轮，patience=5；需要完成真实第一轮后估算服务器耗时。增加适配阶段后，不能沿用 r4 的十余分钟总耗时。
- 每种窗口单独计算训练归一化；200/400 ms 还重新校准 BIR 增益，膜电位时间步使用相应 stride。统计量不能跨窗口复用。
- 100/50、200/100、400/200 ms 的 8 秒录像分别为 159、79、39 步。大窗口减少骨干步数，但每步事件更多、等待更长；最早事件的算法等待上界分别约为 100/200/400 ms，再加计算耗时。
- 三组保持相同每窗通信预算，报告时须同时列每秒通信量，不能把每窗预算直接当成同一每秒预算。Pd/Fa 的分组时序受窗口变化影响，比较须注明协议。
- `training_energy` 是冻结头阶段的测量，不能代替含骨干适配的整项训练能耗；GPU 板卡能量也不是神经形态芯片能量估算。

服务器实验的目的：检验窗口扩大和骨干适配是否创造有用的互补信息。各阶段按固定初始参照筛选验证 IoU 提升且 ACC/Pd 不降、Fa 不升的候选；无合格候选时保留初始候选。这保证选择规则，不保证测试集增长，也不要求更大的窗口胜出。
