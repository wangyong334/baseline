# 本地计算成本核对

2026-11-11。结论：共享源编码确实消除了重复的源特征 MLP，但这不自动产生 GPU 加速。当前实现每次重审仍有查询相关门控、非线性重新赋值、状态与统计量更新。在不缓存查询—源关系的执行路径上，本次 GPU 合成实验仍慢于原 V11。离线 minibatch 内复用固定关系投影，并适当增大 batch 后，两个测试规模的耗时接近或低于旧实现；这不是同精度速度证明，也不是完整训练或在线系统吞吐量。

## 比较口径

- 硬件：RTX 5060 Laptop GPU，8 GB；PyTorch 2.11.0+cu128；float32、`no_grad`，GPU 同步墙钟计时。
- 每项预热 2 次，重复 5 次，表中为毫秒中位数；原始 JSON 保留每次测量和范围。
- 两个规模分别为源事件数 N=10,000 / 查询数 Q=500，以及 N=50,000 / Q=2,500。这个 Q 仅为示例，不是产品规定的出生比例。
- 两模型使用相同源 ID、位置、极性、初始分数、相对时空关系；过去 10 窗、当前 1 窗、后续 10 窗，每窗 16 个槽，共 K=336。每个查询完整运行年龄 0 到 10，无提前退出。
- 旧模型是 `SpikingDecisionNeuronsV11(audit='reaudit', rho='mean', dim=64, heads=4)`；新模型为 `SharedSequentialModel` 默认配置。参数分别为 52,436 和 4,906；二者结构与容量不同，均为随机参数，没有做等精度训练。
- 旧实现每个 query batch 编码邻居一次，再循环各年龄；新实现的共享源编码一次/整组，源读取与关系投影可选择逐年龄计算或在 batch 内缓存。
- 不包含 BIR、邻居搜索、数据传输准备、反向传播、VoW 和提前退出。CUDA event 时间也有记录，但不是 profiler 对所有 kernel 的时间求和。
- 输入源编码复用比 Q×K/N 均为 16.8；不能将此比值当作整网加速比。

## 保留的结果

每格依次为 N=10,000 / N=50,000 的耗时（ms）。不同执行轮次的旧模型耗时也保留，避免跨轮次选择最佳分母。

| 版本 / batch | V11 | 新模型，逐年龄关系计算 | 新模型，关系缓存 | 新模型，关系缓存并裁去未来槽 |
|---|---:|---:|---:|---:|
| 初版 / 128 | 61.72 / 300.83 | 106.58 / 611.15 | 未实现 | 未实现 |
| 加入关系缓存 / 128 | 60.75 / 291.24 | 97.86 / 552.18 | 78.99 / 411.66 | 82.03 / 420.41 |
| 加入关系缓存 / 256 | 43.11 / 211.33 | 56.29 / 414.78 | 40.29 / 222.17 | 45.54 / 220.73 |
| 等价算子优化后 / 256 | 40.80 / 206.68 | 51.28 / 330.05 | 31.18 / 202.23 | 31.98 / 193.72 |

最新未裁剪缓存路径相对同轮 V11 的耗时比为约 1.31×、1.02×。第二个规模已接近测量波动范围，不能声称稳定显著加速。逐年龄关系计算路径仍更慢。改变 batch 对结果影响很大，说明“小参数量”不足以预测 GPU 执行速度；这些结果与大量小算子开销相符，但尚未用完整 kernel profiler 证明每种开销的占比。

最新 batch=256 的额外 PyTorch 分配峰值：V11 约 138.1 / 138.5 MiB，新模型缓存路径约 51.0 / 61.8 MiB。这是在驻留输入和模型之外测得的推理临时显存，不能外推到包括反向传播的训练显存或端到端峰值。

## 已执行的等价优化与语义核对

1. `prepare_pairs` 缓存源 gather 与相对关系投影，保留梯度；每个年龄仍重新计算与当前状态有关的权重和值，并重新施加因果掩码。缓存不能跨优化器更新复用，也不作为无限在线 pair 缓存。
2. 初始先验上下文在 state 的 `anchor` 中复用，避免每次重审重新运行不变的先验 MLP；各 state 字段具有独立存储，防止流式原位回填相互覆盖。
3. 已经置零的不可见 source context 不再重复乘同一个掩码；加权上下文聚合使用 `bmm`，避免创建大尺寸乘法中间张量。
4. 相对关系归一化尺度为设备 buffer；标量 age 直接在目标设备创建。

没有删掉“新证据改变旧证据值”的非线性分支，也没有把旧邻居压成不可重读的单一总和。Torch 1.9 CPU 下 19 项核心测试通过，包括固定年龄下改变新证据内容引起旧值变化、未来屏蔽及其零梯度、NaN padding、重复前缀不漂移、batch 不变性、缓存输出和梯度等价。后三项算子优化前后，固定探针的全部前缀分数与上下文完全相同，参数和源输入梯度最大绝对差为 4.77e-7。

## 当前尚不能成立的声明

- 不能据此说“整个模型 GPU 加速 16.8 倍”“参数少十倍所以速度快十倍”。
- 不能将离线关系缓存的结果直接作为在线系统速度；在线仍受活跃查询数、候选搜索、数据搬运和真实退出分布影响。
- 不能把 `no_grad` 结果当作训练加速比例，完整反向传播还需服务器实测。
- 缓存和更大 batch 是执行改进，不能独立构成论文科学创新。科学贡献仍需由保留旧证据重审能力、成本一致的停止策略及任务结果验证。

## 复现与原始文件

```powershell
.\.venv-gpu\Scripts\python.exe tools/bst/benchmark.py --device cuda --sources 10000 50000 --queries 500 2500 --batch-size 256 --repeats 5 --warmup 2 --out Res/bst_local_20261111/kernel_benchmark_rerun.json
```

原始文件在 `Res/bst_local_20261111/`：

- `kernel_benchmark_before_cache.json`：首轮负结果。
- `kernel_benchmark.json`：关系缓存 / batch 128。
- `kernel_benchmark_batch256.json`：扩大 batch 的对照。
- `kernel_benchmark_optimized_batch256.json`：当前等价算子优化后。
- `core_optimization_equivalence.json`：输出和梯度核对。

计时脚本为 `tools/bst/benchmark.py`，可调整 device、规模、batch、重复次数及输出路径。测试都是本地机制与执行探针，完整服务器训练和数据集级端到端速度仍待验证。
