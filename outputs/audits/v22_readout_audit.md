# V2-2 读出审计（2026-09-26）

结论：已有实验说明当前实现没有有效收益，但尚不足以说明核心设计在正确实现后仍无效。本次发现四项可复现的读出／状态管理缺口。值得一次限定范围的修复复评，不据此承诺真实数据收益，也不重新展开假设库设计。

## 核查范围

- 静态核查：`model/attribution_readout.py`、`model/target_hypotheses.py`、`train_stream_v2.py` 的注册、更新、读出和回填顺序。
- 与服务器一致的 Python 3.8.20 / PyTorch 1.9.1 CPU 环境：原有 19 个 V2-2 测试通过。
- `tools/audit_v22_readout.py`：四个定向探针，结果在同目录 JSON 文件中。
- 三项探针注入受控状态以隔离读出行为；结束探针通过实际假设库更新处理合成运动目标。它们不是数据集实验，不估计可恢复的 IoU。
- 本地未找到真实事件导出 NPZ 或模型权重，未重跑真实数据。Claude 在线设计页访问失败；设计核查依据用户截图及本地公式、注释和实现。

## 发现

1. **未来门控截断负修正（设计层面）**：`_readout` 只在后验相对密度通过门限的位置计算比值。受控例中原相对密度 0.204、未来相对密度 0.00150，裸比值修正 -1.270，实际为 0。未关联过目标不等于背景，但先前有关联、后来被排除是另一种情况。现有规则将二者都回退。
2. **先择优后过滤可靠性（设计／执行顺序）**：支持不足的已确认假设可以先取得最大密度，再被支持数门控剔除，却不会回退到另一个可靠假设。受控例中可靠假设单独存在时修正 +0.981；加入支持不足的假设后为 0。
3. **结束时提前丢失回溯历史（生命周期管理）**：读出只遍历存活已确认假设。实际合成轨迹结束后，仍在等待的旧事件失去读出支持。默认 d=5 的例子中，保留历史时 11 个事件修正非零，删除后均为 0；最大差约 0.110。此例只证明行为变化，不证明真实数据影响很大。
4. **合并改变冻结参照（身份／历史管理）**：合并删除假设，但没有把待查询事件的冻结参照映射到保留的身份。受控例中两个假设当前分布一致，只是其中一个拥有历史快照；合并后快照参照变为均匀参照，在没有新观测的情况下修正从 0 变为 +2.374。

原有测试未覆盖这些路径：锐化测试检查分布函数本身；重复假设测试调用的复制函数同时复制了快照，未测试真实合并后的身份变化；结束测试只检查对象被删除。

## 诊断口径修正

`target_case1 / target` 约为 82%，只表示事件使用历史已确认假设的快照参照，不表示这些事件的修正等于零。s37 的 d2 统计为覆盖目标 61,832 个，其中 42,079 个有正修正。应另外统计修正幅度、方向及是否实际改变分类。不能把 case1 比例当成零修正比例。

## 最小收尾范围

1. 可靠性筛选应在候选择优之前完成。
2. 对有历史关联的事件，允许在同一假设的分布收缩／移开后计算负修正；无历史也无可靠未来关联的事件仍回退，不把所有背景强制扣分。
3. 合并及结束不得破坏待输出事件的冻结参照和可用历史；结束对象可在待查询窗口清空后再释放。需明确身份继承规则，不能靠任选一份历史快照修补。
4. 将以上行为变成机制回归测试，再用同一 s37 权重、同一延迟和原四项指标复评。单独记录受这些修复影响的事件与修正方向。

不在此次修复中添加新神经元、学习模块、更多状态或大规模调参。复评若没有明确净收益，冻结 V2-1，停止该归属实现并进入 V3；若有收益，再判断其幅度是否值得假设库成本。

## 旧六项创新的处置

- 证据积累、背景归一化、mark/强度双头损失：保留已有效部分，补必要消融，不强行增加新模块。
- 告警与 anytime 理论：与逐事件主任务分开；自适应发布为可选延迟实验。
- 极性偶极与时间矩：保留；正则坐标和二阶矩是未验证候选，不是必须补齐的 V2 功能，可移到 V3 表征研究。
- 合成验证：补本次暴露的机制覆盖；不为凑理论贡献强做不相关的标度律曲线。

本次只新增审计脚本和报告，未修改模型、读出、默认配置或既有实验结果。
